# PDF engine in Open Office

Open Office incorporates the Rust PDF object model, parser, renderer, editing engine and egui workspace from [PdfCraft 0.8.0](https://github.com/storytold/pdfcraft/tree/f65f7330418e8121ebe59c01003da899340ceee9), commit `f65f7330418e8121ebe59c01003da899340ceee9`. The upstream code is MIT OR Apache-2.0; this integration selects MIT and retains both original license texts, NOTICE and original asset attribution. It is an independent modified integration, not an official release or endorsement by the original authors.

Local modifications add `vendor/office-pdf/apps/open-office-host` with independent live document sessions, revision-bound save receipts and file-action forwarding. The Open Office shell owns opening, saving, printing, document tabs and appearance; the Rust workspace owns document editing and layout. Source identifiers and application metadata use Open Office names. Legacy protocol identifiers needed to read existing documents are retained as explicit compatibility data. These changes do not remove upstream copyrights or claim sole authorship of the engine.

The editor runs as local WebAssembly inside the application. The previous Python/MuPDF process and browser PDF.js runtime are removed from the current product. Independent development inspectors remain outside the shipped application. The current build still uses the upstream permissive hayro/lopdf parser and renderer components, including its vendored patches; this integration is not a claim that every PDF primitive was authored by Open Office.

Simplified Chinese is the embedded interface default. The editor uses original Open Office SVG interface artwork. Restricted upstream trademark artwork and the promotional screenshot containing it are excluded. The original upstream attribution files retained in this legal directory describe upstream assets and optional inputs; they do not claim that all such assets are shipped here.

Fonts use the existing pinned local LXGW WenKai, DejaVu Sans and Noto Sans Symbols 2 resources plus the upstream Latin fonts and egui defaults. No Source Han/Noto CJK face is added to this PDF engine. PDF technical CMaps and standard-14 metrics are retained under their original licenses. Optional shared-font checkout, update services and agent network servers are not enabled by this integration.

The original PDF object graph and unknown data are retained by the upstream engine. Signed, encrypted and advanced documents can have import/editing limitations; this integration does not claim complete compatibility. Opening an imported document uses the shell's first-save copy protection. Successful export alone never clears unsaved status: the shell must acknowledge the exact current document and revision after its write succeeds.

The source manifest records unmodified upstream file hashes. The build manifest at `public/office-pdf/manifest.json` separately records actual modified sources and generated WASM/JavaScript. The dependency inventory and the vendored patch directories retain precise source and license information. Actual verification results are recorded in the project integration notes rather than inferred from upstream feature lists.
