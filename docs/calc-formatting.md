# 电子表格选区格式与局部文字格式

本轮通过捆绑的本地 Calc WASM 打开真实 XLSX，核查选区格式、数字格式和单元格内富文本，修正中文工作台的三处行为。以下混合显示说明仅指应用自己的中文工作台，不表示内嵌原生菜单的显示也被修改。

- 多个单元格字体、字号、颜色、对齐或数字格式不同时，工具栏显示“混合格式”，不再把左上角样式当作整个选区。混合加粗、斜体或换行按钮再次点击会明确启用该属性。选择一个新值只写该属性。
- 单元格内不同文字片段的字体修改会通过原生文字光标应用。原先仅修改单元格属性会返回成功，但片段内明确的字号、文字颜色和斜体仍保持原值。现在保留文本、公式和未指定的片段属性。
- 对混合数字格式选择“常规”时，原生内核第一次写入可能只统一语言。本轮在同一次撤销操作中重新应用同一常规格式，让百分比、千分位和文本格式真正恢复为常规。

“无填充”仅移除背景填充，不清除数据、公式或其他格式。数字格式也不改变存储值与公式，和数据类型转换不同。以上能力未增加“清除所有格式”或“清空单元格”操作。

## 状态读取与边界

原生 `getPropertyStates` 一次读取固定数量的属性。`AMBIGUOUS_VALUE` 标为混合；失败、非法状态或超过 1 万格的选区标为未确认。没有逐格扫描整列、整表。当前保持原 `format` 字段作为兼容的左上角值，新增 `mixedFormat`、`unavailableFormat` 和 `richTextFormat`；界面先看状态，不把未确认值当实际统一样式。

字体读取覆盖 Latin、Asian、Complex 三套原生属性，但不会仅因三个文字系统使用不同字体就误判混合。背景完全透明时忽略不参与绘制的颜色差异；透明状态本身混合则仍显示混合。

内核的单元格属性状态不能完整表示单元格内局部文字属性。原生 `CellFlags.FORMATTED`（512）查询可发现含局部格式或多段文字的单元格；这些格的文字状态不能确认时会明确显示“格式未确认”，仍允许用户选择新值。该查询不使用 `EDITATTR`（256），后者在固定内核的查询接口里不会返回这些格。

单元格样式继承、条件格式计算以及最终渲染效果不等同于直接格式状态。本轮没有实现这些高级显示效果的全量归并分析，也不宣称任意视觉差异都能被混合状态捕获。

非连续多选和无法读取范围的选择不允许从格式工具栏提交，避免只修改第一段；没有显式目标的原生工具请求也拒绝未知选择。明确指定 `range` 的 API 仍可操作该确定目标。超过 1 万格需缩小选区；文字格式一次最多处理 256 个含局部格式的格。

## 编辑与撤销

文字属性先查询所有富文本目标，核对范围、工作表、预算、光标能力和属性支持，再开始修改。普通范围与富文本光标写入在同一个原生撤销组中；一次撤销/重做包含所有格。修改既不重建富文本，也不调用 `setString`。数字格式登记放在能力预检之后、单元格写入之前。

这些预检阻止已知的不支持操作，不表示能够保证原生运行时崩溃情况下的事务回滚。格式为空的界面占位项不会自动提交，也不会转换成字号 0。

## 可重复验证

夹具：`tests/compatibility/calc-formatting/mixed-format-source.xlsx`，由同目录 `make-fixture.py` 独立生成，含数值、公式、前导零文字、不同字体/边框/底色/对齐和 RED/BLUE 局部文字片段。

- `tests/calc-tools.test.mjs`：混合状态、未知状态、整表预算、透明背景、无效选择、富文本上限、预检及撤销边界。
- `tests/browser/calc-formatting.cjs`：真实 WASM 打开、原生状态、格式修改、一次撤销/重做与 XLSX 保存。支持 `CALC_FORMAT_OUTPUT`。
- `tests/browser/inspect-calc-formatting.py` 和 `audit-calc-formatting.py`：独立解析导出 XLSX，对内容、公式、每格未修改格式及富文本属性做 252 项断言，不复用产品读写代码。
- `tests/browser/calc-formatting-ui.cjs`：实际 Vue 工具栏操作、混合占位、原生富文本修改、撤销/重做、无填充、常规数字格式、保存重开和大范围导航拒绝。支持 `OFFICE_WORKBENCH_URL` 与 `CALC_FORMAT_UI_OUTPUT`。

本轮证据目录：`test-results/calc-format-iteration/`。初始失败及原生接口探查单独保留；最终结果以 `final-native/native-report.json`、`final-native/export-audit.json` 和 `ui/ui-report.json` 为准。所有范围外的既有兼容性结论不因本轮测试自动变为已解决。

混合/未确认的色块会覆盖显示提示，并提供明确的“用此色”按钮（标题列出候选色值），因此用户也能统一为恰好等于原左上角的颜色，不依赖原生颜色选择器对“选择同一颜色”触发 change 事件。多选和未知选区的拒绝由工具栏禁用、事件函数守卫与省略目标的原生接口检查共同执行；当前非连续选择的自动化证据是模型合同测试，并非鼠标 Ctrl 多选的端到端演示。
