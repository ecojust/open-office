# Open Office 0.7.0 · Rust 文字内核第一阶段

本版为 Rust 文字内核功能预览。发布流程仅在全部必要构建与安装包检查通过后提供附件，具体结果见本次 Actions 记录；下文分别说明开发验收与发布要求。

默认“文字文档”入口现在由自研 Rust 内核完成基础 DOCX 的新建、打开、编辑、排版与保存。桌面通过 Tauri 调用原生 Rust，浏览器运行同一份代码编译出的 WASM。Vue 显示 Rust 返回的字形轮廓、分页、光标和选区，正文模型与编辑历史由 Rust 管理。

第一阶段支持中英文正文、可用单色 emoji、组合字符、输入法组合事务、粗体、斜体、字号、RGB／自动文字颜色、左中右对齐、撤销重做及多标签。每份文档最多 10,000 个 UTF-16 单元（含段落分隔）、500 段、200 页、32 条撤销历史；同时最多打开 4 个 Rust 文档会话。字号为 8–72 磅、半磅步进，字体使用随应用提供的固定集合。

导入严格限制在已实现的 DOCX 语义中。图片、表格、编号、页眉页脚、修订、语言、主题格式等未支持的有效属性会明确拒绝；失败导入保留当前文档和历史，不会自动切换引擎。受支持的样式按有效格式展开保存，首次保存导入文件生成副本。暂不提供 Rust 文字打印、PDF 导出、任意字体或与其他办公软件完全一致的分页。

复杂文字文档仍可从“兼容编辑器”入口使用内嵌办公引擎。旧轻量文字预览、电子表格、独立演示和 PDF 工作区保留各自实现，整个应用尚未迁为 Rust。新文字链使用 `roxmltree` 通用 XML 库、`rustybuzz` 字体塑形、`ttf-parser` 轮廓读取、Unicode 库及固定字体；LibreOffice 用于独立研究和对照测试。**当前没有证明相比旧引擎的性能提升。**

2026-10-15 的开发验收已通过 36 项 Rust 测试、899 项 Node 和 83 项 PDF 后端测试，以及 8 组真实浏览器验收。真实 WASM 与原生 CLI 完成 67 次协议请求对照；独立完整 DOCX 经实际导入、两轮导出重开及外部 ZIP/XML 校验。原生 LibreOffice 重存带来的未支持 `kern`／`lang` 属性保留为拒绝负例，不据此宣称任意 Word 文档兼容。浏览器组合事件测试不等于系统输入法验收。

前端生产构建及 Linux 原生编译通过。本地缺少 WebKitGTK 子进程，窗口启动失败，因此该环境的真实 Tauri IPC 运行检查仍受阻；编译成功和 CLI 对照不能替代此检查。

发布前，Windows x64、macOS ARM64 和 macOS Intel 安装包必须通过本次构建与完整应用自检，包括新增 Rust 文字内核的真实 IPC 新建、编辑、排版、导出重开和失败保护，以及原有工作区检查。任何必要报告缺失或失败都应阻止发布。Intel 安装包使用 Rosetta 运行检查，尚不代表真实 Intel 显卡测试。本次提交、构建记录和安装包结果以发布页附带的 Actions 链接为准。

macOS 仍采用 ad-hoc 签名，未进行 Developer ID 签名或公证；Windows 没有商业代码签名。发行包含多种许可证组件，完整说明见[集成分发许可](../../DISTRIBUTION_LICENSE.md)与[第三方许可清单](../../THIRD_PARTY_NOTICES.md)。
