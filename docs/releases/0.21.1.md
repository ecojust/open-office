# Open Office 0.21.1 · 工时标签与排期图片导出

本版完善「计划排期」的工时显示：悬停事件可查看总天数，人员月度统计改为紧凑标签，导出的 PNG 也完整包含各月工时。

## 更新内容

1. **事件悬停工时。** 提示中增加「工时：X 天」，沿用月度统计规则：全天计 1 天，上午／下午计 0.5 天，扣除周末及法定、自定义假日。修改日期、高度、假日或撤销后即时更新，显示周末和假日不会改变工时。整体计划显示自身工时，仍不计入人员月度合计。
2. **紧凑月度标签。** 人员姓名与角色显示在同一行，下方用 `26.10-40%` 形式的标签显示每月工时占比，每行两个。悬停标签查看完整年月、已排／可排天数和计算口径；月份多时可独立滚动，长姓名及角色省略显示。
3. **「人员 / 事件」切换。** 切换按钮去掉「模式」字样，原「全局」更名为「事件」，相关表头、导出图片和使用说明同步更新。
4. **PNG 完整导出月度工时。** 图片左侧以两列标签展示所有月份。人员视图显示每人的月度占比；事件视图显示该事件负责人的月度汇总，并注明统计口径。月份较多时，仅在导出布局中按 28px 刻度增高轨道，不修改原排期行高，仍保留事件全天／半天比例及上下午位置。
5. **移除导出事件数量。** PNG 标题、轨道和页脚不再显示事件数量，保留不带数量的隐藏日期提示。数据文件和 JSON 导出仍保留完整排期。

## 使用与兼容

操作说明及图片示例见[计划排期使用说明](https://github.com/ecojust/open-office/blob/master/docs/project-scheduling.md)。月度占比继续以当月项目范围内的工作日为分母，最多保留一位小数；无可排工作日显示「—」。

本版不增加排期文件字段，与 0.21.0 使用相同格式。导出行高和工时均为临时计算，不改变项目文件、保存状态或界面轨道高度，也不增加运行时依赖。PNG 继续遵守最大边 16384 像素、总像素 2400 万的限制，超大排期会等比缩小。

## 验证与安装包

944 项自动化测试及完整生产构建完成验证。本轮通过 13 项工时与 PNG 浏览器检查，并复验原有 11 项布局和导出检查：覆盖姓名／角色同行、两列标签、悬停工时、实时更新和撤销，以及真实 PNG 中的月度占比、隐藏提示、37 个月完整展开、导出轨道增高和下午事件位置。

发布流程要求 Windows x64、macOS Apple 芯片及 macOS Intel 的原生构建和检查通过，并对 Intel 安装包执行 Rosetta GUI 验收、对 ARM 安装包执行 macOS 26 输入编辑验收。发行页提供三个安装包、对应源码和 `SHA256SUMS`。

Intel 验收使用 Rosetta；应用仍处于 Alpha，未配置商业代码签名或 macOS 开发者公证。
