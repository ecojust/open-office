# Open Office 0.6.1 · DOCX 行距兼容修复

本版修复轻量文字编辑器无法打开部分有效 DOCX 的问题：文档只指定行距规则、未指定数值时，现在按 LibreOffice 的默认值读取，固定值与最小值为 12 磅，自动行距为单倍。父子样式、文档默认值和直接格式中的继承关系分别保留，保存时写入明确数值，避免保存重开后改变行距。

只有段前／段后间距的设置继续保留原有行距。空字符串、未知规则、重复节点和范围外数值仍明确拒绝；打开失败不会替换当前文稿或破坏撤销记录。

验证：

- 类型检查、865 项 Node 测试、83 项 Python 测试及前端构建通过。
- 固定 LibreOfficeDev 版本的六份完整原件、27 个段落和 30 份原生 DOCX／ODT／PDF 保存结果通过 1001 项独立文件证据检查。
- 新增浏览器专项 5 组、段落间距回归 10 组、编解码回归 21 组、Rust 包协议回归 34 组通过；包括七次实际 LibreOffice 重存重开，以及面板编辑、撤销重做、格式来源保留和非法输入拒绝。
- Rust 回归核对 138 份完整语料，执行 593 次真实 CLI 调用和 405 次受控传输。相关语料、检查器和专项命令随源码提供，详见 `docs/independent-word.md`。

发布流程要求 Windows x64、macOS ARM64 和 macOS Intel 安装包全部构建成功，并通过规定的实际应用自检。其中 Windows 与 ARM Mac 直接运行，未修改的 Intel DMG 转移到 ARM Mac 后通过 Rosetta 检查。自检包含实际 Rust IPC、文档编辑、保存重开及 PDF 独立回读；详细结果见本次 Actions 记录。

轻量文字编辑器仍为预览，仅支持已实现的 DOCX 正文子集，尚无复杂分页、表格和图片。本次兼容对照限定一个 LibreOfficeDev 版本及这些样例，未验证 Microsoft Word；既有原生自检不等同于全部新增行距场景已在每种 WebView 逐项检查。本版没有扩大行距数值范围，也不作新的性能承诺。

完整文字、表格和演示工作区继续使用现有办公引擎，并非纯 Rust 实现。0.6.0 说明中的其他限制仍适用，包括表格首次画面及初始工具栏交互、复杂演示编辑、PDF OCR 和证书签名功能。Intel 的 Rosetta 检查不等同于真实 Intel GPU 测试。

macOS 安装包采用 ad-hoc 签名，未进行 Developer ID 签名或公证；Windows 安装包没有商业代码签名。附件包含三种安装包、对应提交的源码 ZIP 和 `SHA256SUMS`。集成发行包含 AGPL / GPL 等组件，许可与对应源码见 `DISTRIBUTION_LICENSE.md` 和 `THIRD_PARTY_NOTICES.md`。
