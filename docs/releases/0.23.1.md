# Open Office 0.23.1 · PDF 与演示性能优化

本版改善 PDF 和演示文稿在全屏编辑切换、连续缩放时的卡顿，修复 PDF 延迟绘制可能无法自动完成的问题。

## 更新内容

1. **复用普通与全屏尺寸。** 页面最多保留两种精确尺寸的绘制结果，返回已经显示过的尺寸时直接复用，减少重复绘制与纹理上传。额外尺寸计入原有缓存预算；PDF 的页面缓存与演示的画布缓存上限保持不变。
2. **减少连续缩放的重复工作。** 演示在静态整页连续缩放时先显示已有画面，尺寸稳定后自动绘制清晰结果。文字编辑、动画及画布外内容继续按实际变化绘制。
3. **修复 PDF 缩放计时与自动收尾。** 恢复浏览器内核中失效的绘制耗时计量，使复杂页面能够合并连续缩放请求；延迟任务在停止操作后会自动继续，不再依赖下一次鼠标或键盘输入才能完成清晰绘制。
4. **保留翻阅与编辑行为。** PDF 继续预取相邻页面。内容修改、撤销、重做和文档切换会更新或清理旧尺寸缓存，避免显示过期内容。

## 性能验证

在相同 Chromium 软件 GPU 环境、相同样例文档和操作脚本下，实际 Vue 与 Rust/WASM 编辑器的主线程长任务统计如下：

| 应用 | 重复全屏切换平均阻塞：优化前 → 优化后 | 连续缩放阻塞总耗时：优化前 → 优化后 |
| --- | ---: | ---: |
| PDF | 783ms → 57ms | 3715ms → 1627ms |
| 演示 | 183ms → 53ms | 4722ms → 2120ms |

全屏数据取普通与全屏尺寸完成首次绘制后的四次切换；优化后这四次切换均无需重新上传页面纹理。每组前后对比使用相同等待时间，并计入延迟清晰绘制完成前的开销。两种尺寸的最终页面像素与优化前一致。

这些数字是指定样例的主线程长任务统计，不是一次操作的完整响应时间，也不是 macOS 安装版实机性能。首次遇到复杂页面或新的显示尺寸仍需要 CPU 绘制。

## 使用、验证与安装包

文件格式及 MCP 接口沿用 0.23.0。无需修改设置，打开 PDF 或演示文稿即可使用上述优化。

53 项 Rust 回归通过，包括 PDF 的 45 项及演示的 8 项；覆盖尺寸复用、缓存预算、内容失效、编辑历史和停止输入后的绘制调度。浏览器检查验证了最终清晰画面、重复切换像素一致、翻页、缩放，以及全屏后继续编辑、撤销重做和退出。完整生产构建通过。

发布流程要求 Windows x64、macOS Apple 芯片和 macOS Intel 的构建与检查通过，并对 Intel 安装包执行 Rosetta GUI 验收、对 ARM 安装包执行 macOS 26 输入编辑验收；逐平台结果以本次 Actions 记录为准。发行页提供三个安装包、对应源码和 `SHA256SUMS`。

Intel GUI 验收使用 Rosetta；应用仍处于 Alpha，未配置商业代码签名或 macOS 开发者公证。
