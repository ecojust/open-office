# PDF 正文替换与交互对象保护

2026-10-14 的后续源码复查针对原文替换、表单、批注和链接的组合，未新增完整涂抹工具，也没有发布或验证新安装包。

## 已复现的问题

1. 直接对文本框显示区域执行正文替换，后端曾返回成功，却保留原字段的 `/V` 与 `/AP`，只在页面增加了替代文字。保存文件同时包含新字与旧字段值，不能视为替换表单或删除旧内容。
2. 页面原本存在另一处待处理的涂抹批注时，底层 `apply_redactions` 会一次应用本页全部涂抹。修改普通正文曾意外删除远处文字，并移除那条待处理批注。

真实小样本及前后 PDF 保存在 `test-results/highlight-pdf-followup/`；[基线记录](../test-results/highlight-pdf-followup/baseline.json) 记录两种成功响应中的实际错误行为。

## 当前处理

- 原文替换前检查原字区域和新文字排版区域。任何一区域与表单字段、批注或链接相交，都会明确拒绝并保留原文件；表单内容应通过填写功能修改。
- 编辑页只要存在待应用的涂抹批注，就拒绝正文替换，避免连带执行。其他页的待处理涂抹不影响本页正常操作，也不会被应用。
- 一页最多检查 5,000 个相关对象；超过上限或存在无法可靠定位的对象时拒绝替换，不使用不完整检查结果继续操作。
- 普通、不相交的正文仍可以真正删除原字并写入替代文字；此前表单填写、共享样式与页面组合保护继续保留。

这个范围不包含可靠清除文档所有敏感信息的产品承诺。新增文字、高亮或图片覆盖不能作为安全删除；此处保护的是已有正文替换操作，不是新建或应用用户涂抹批注的工具。

## 验证

`pdf-backend/tests/test_text_object_intersection.py` 新增 **7/7** 通过，完整 PDF 后端 **68/68** 通过。覆盖源区域及扩大的排版区域与控件相交，高亮、便签、手绘和链接相交，同页及异页待处理涂抹，非零裁切框下四种旋转，以及检查预算。

允许的正文替换保存后，比对未编辑控件的字段值、属性、外观字节及区域像素；同时比对其他页像素、便签元数据、链接与书签。字段仍能通过表单工具继续填写。最终 PDF 另由 Poppler 读取，确认正文旧值已消失、新值存在，而无关表单值和 AcroForm 保留。
