# Open Office PDF 工作区

当前工作树已把 PDF 接入本地 Rust/WASM 工作区。外层窗口统一管理新建、打开、保存、另存、打印、主题和多文档标签，PDF 界面只负责文档操作。原始来源、许可及本地修改见[PDF 集成声明](../public/legal/office-pdf/OPEN-OFFICE-INTEGRATION.md)。这些源码修改尚未发布为新安装包。

## 编辑和保存

工作区提供阅读、可提取文字编辑、新增文字、批注、表单、搜索、书签和页面整理工具。每个标签持有独立文档、视图和撤销历史；打开失败的候选文件不会替换已有标签。新增或已修改的输入先完成提交，再生成 PDF 字节。

0.12.0 将常用编辑和视图操作移到文档操作栏，其余已接通的功能放入高级菜单。可视签名和图章保留直接按钮；可视签名是页面上的签名外观，不代表数字证书签署。删除操作先弹窗确认，具体可用范围仍受下列能力边界约束。

0.13.0 增加“图章署名”设置，供新动态图章和批注使用。设置在本机保存并在 PDF 标签间共用，不从文件作者或系统登录名推断；未填写时不署名，不再使用默认 `Guest`。修改署名不会改写已放置图章。动态图章的中文作者行复用随包字体轮廓绘制，避免标准西文字体把姓名替换成问号。发布流程增加图章导出和重开的 Rust 回归，实际构建与运行结果以对应提交的记录为准。

新增中文文字使用随包字体，支持中英文混排和断行，保存后保留可提取的文字。遇到当前字体无法显示的字符时会提示失败，不覆盖原文档。放弃编辑并关闭标签时，会先清理尚未处理的输入法事件，再允许切换到其他文档。

保存绑定文档和修订号。只有文件写入成功且回执仍对应当前修订，才会清除未保存状态；保存期间继续编辑不会被旧回执误标为已保存。切换标签保留当前会话。0.12.0 桌面版打开 PDF 后直接保存回原文件，需要副本时使用“另存为”；外部文件修改检查仍生效。

## 当前边界

- 最多同时打开 8 个 PDF，应用导入限制为 40 MiB；底层会话另设 64 MiB 的防护上限。
- 需要打开密码的文件目前在预检阶段拒绝，尚未接入外层密码输入对话框；可正常读取的受限文件仍由引擎检查编辑权限。
- OCR 识别需要识别模型；当前 WASM 工作区未接入模型加载，没有模型时识别按钮禁用，批量识别入口隐藏。
- 数字身份创建/导入、数字证书签署和认证流程尚未接通，相关入口隐藏或阻止进入；保留已有签名的查看与验证，以及普通填写和手写签名。不承诺完整证书信任验证。
- 图片文件插入/替换、附件打开/保存、批注与表单数据文件导入导出、文件水印/背景及证书导出尚未接入全局文件操作，相关入口隐藏；保留已有图片的属性编辑、文字水印和颜色背景。
- 内部格式转换导出、图片/文字导出、页面提取/拆分、跨文件比较和批处理暂不开放。页面提取在工作区入口处拒绝，避免未生成新文件就删除原页；全局 PDF 保存、另存和打印不受影响。
- 不承诺跨页正文重排或复杂 PDF 的完全保真。
- 全局文件操作由外层提供；独立批量建档、合并成新文档等尚未接入的入口隐藏，不伪装成可用功能。
- 浏览器、操作系统打印对话框、原生文件对话框及不同平台的 WebView 必须分层验收。浏览器通过不能作为 macOS 或 Windows 安装包通过的证据。

## 验证入口

`npm run pdf:build` 构建第四套 WASM；`npm run pdf:check` 核对源码和产物摘要。`node tests/office-pdf-client.test.mjs` 验证保存回执、输入提交和会话隔离；`npm run test:browser:pdf` 在真实画布中编辑、保存、重开，并用独立测试工具读取导出 PDF。原生验收复用真实挂载编辑器，并核对安装目录和实际加载的引擎摘要。

`npm run test:browser:pdf-toolbar` 另外检查操作栏在不同宽度下的布局、工具与视图切换、手写签名和图章放置，以及删除确认、取消和撤销；导出后由独立 PDF 检查器核对签名与图章，再在实际编辑器中重新打开。

测试报告只代表其记录的实际源码、产物和运行平台。[旧 PDF 工作区记录](history/pdf-0.4-capabilities.md)属于历史版本，不覆盖当前引擎。
