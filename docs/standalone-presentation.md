# 独立演示工作区

更新：2026-10-13。本轮将 PPT 从原办公引擎中拆出，使用 Vue 界面、独立文档模型、SVG 编辑画布和直接 PPTX 读写。新建、打开、编辑、保存与放映均走此路径。文字、电子表格和 PDF 工作区不属于本轮内核替换范围。

这是当前源码的实现与验收记录；此前发布的安装包不包含本轮替换，新的 Windows/macOS 安装包尚未验证。

## 已实现

| 范围 | 功能 |
| --- | --- |
| 页面 | 新建、复制、排序、删除、重命名、隐藏、版式、比例、纯色背景、备注 |
| 对象 | 文本、矩形、椭圆、直线、图片、表格、柱状图、条形图、折线图、饼图 |
| 编辑 | 点击与多选、拖动、缩放、旋转、位置与尺寸、对齐、分布、层级、组合与取消组合 |
| 文字与数据 | 双击文字编辑，字体、字号、颜色与基础段落属性；表格单元格和图表类别、系列、数值编辑 |
| 历史与保存 | 撤销重做、文稿内对象复制粘贴、保存与另存 PPTX、保存后继续撤销；未应用草稿、取消保存、关闭确认及过期导出保护 |
| 放映 | 从首页或当前页开始、跳过隐藏页、键盘翻页、备注与计时、基础页面转场、本地嵌入音视频 |
| 导出 | 真正可编辑的 PPTX；使用矢量文字、形状、表格和图表的 PDF，中文可检索 |

文件操作与幻灯片工具各一行，右侧属性按需展开。窄窗口默认收起属性，工具行横向滚动，不挤压或撑破整个窗口。选中表格、图表后可打开数据编辑器；快捷键 F5 从首页放映，Shift+F5 从当前页放映，Esc 退出。

## 文件处理与兼容范围

目前接收标准 Transitional PPTX。旧二进制 PPT、ODP、Strict OOXML、含宏、加密或数字签名文件会给出明确错误；需要先转换为支持的 PPTX。不会静默切回旧编辑器。

导入读取主题、母版及版式继承，保留原包文件。常见对象进入独立模型并可编辑，未知对象、SmartArt、OLE、自定义几何、合并表格和复杂图表会锁定并显示提示。原始 XML 和所需包内容在保存时保留；复制页与对象会维护独立的 ID、关系和图表工作簿。

保留文件内容不等于完整显示或播放：高级填充、裁剪、复杂文字排版等预览可能简化，画布文字采用统一样式，修改文字的段落无法保证原有逐字符格式；单独改色或改字号会保留未修改的格式属性。编辑基本图表数据时会按基本图表样式重建。受保护对象显示占位或简化预览。PDF 与放映画面采用当前渲染模型，不能作为任意复杂原件的无损转换器。完整逐对象动画、路径动画、完整母版设计器、审阅、双屏演讲者和视频录制仍未实现。

遇到导入兼容提示时，首次保存默认另存副本。保存取消、发生文件冲突或导出失败时，仍保留未保存内容。外部关系不会自动联网获取；本地音视频能否播放取决于系统支持的编解码器。PDF 是静态页面，不携带动画和媒体。

## 实际验证

本轮在 Linux Chromium 的完整 Vue 应用中操作界面，未通过旧编辑器模拟结果：

- 新建文稿，双击编辑中文，键盘移动，鼠标拖动与缩放，撤销与重做。
- 编辑表格和图表，保存真实 PPTX；独立读取 ZIP/XML 核对对象几何、文本、数据和图表内嵌 XLSX，再重新打开继续修改。
- 导入包含图片、表格、图表、备注的原始样例及 20 页文稿，验证隐藏页、页序与重复保存。
- 导出三页 PDF，独立回读页数、尺寸和可检索中文；字体子集另经 PDF.js、PyMuPDF 和 fontTools 检查。
- 验证 F5、Shift+F5、Home、End、Esc、隐藏页跳过，未保存标签切换及关闭时保存、取消、放弃修改。
- 检查 640、900、1360 像素窗口；PPT 会话中 iframe 数量、旧办公引擎请求、外部网络请求和运行异常均为零。
- 检查未知对象保留、原始包未被改写、复制对象与页面 ID、分组几何、转场与媒体；拒绝危险 XML、宏、签名及越界包关系。
- 使用独立的 python-pptx 读取最新五份导出文件，27 项检查全部通过；核对表格、图表、中文、备注、隐藏页和几何，ZIP 内部关系均无缺失。该检查发现并推动修正了新建表格的标准 OOXML URI，未以自家编解码往返代替外部读取验证。

首次独立内核验收结果：430 项前端与协议测试、28 项 Python PDF 测试、24 项真实浏览器检查通过，`npm run build` 成功。该轮摘要见[测试记录](standalone-presentation-results.json)。后续复杂兼容专项回归已增至 438 项前端与协议测试，最新结果见下方专项报告。

测试入口：`npm run test:browser:ppt-independent`。需先启动 `npm run dev`，详细输出写入 `test-results/standalone-presentation/`。模型与渲染回归位于 `tests/presentation-model.test.mjs`、`tests/presentation-render.test.mjs`，随 `npm test` 执行。

这组测试验证指定样例和操作，不代表所有输入文件或目标桌面 WebView 均已兼容。完整应用的 Word/表格仍使用原引擎，因此本轮也不等于整个安装包已经缩小。

后续扩展的 12 份复杂原件、多轮保存、动画引用与 SmartArt 检查另见[复杂 PPTX 专项](presentation-complex-compatibility.md)，其中明确区分文件保留、画面简化和未实现的播放能力。

## 性能观测

首次独立内核验收的完整浏览器回归中，新建文稿到可编辑约 494 ms，三页复杂样例约 4.73 s，20 页样例约 12.42 s。该轮同时运行构建和其他回归，存在资源争用；较早一轮对应观测为 179 ms、1.99 s 和 4.08 s，不能将其中任一数值当作稳定性能承诺。该轮 20 页阶段 CDP 记录的 JavaScript 已用堆约 14.8 MiB，`performance.memory` 则为约 37.4 MiB，两者采样口径不同。这里记录的是开发服务器、指定样例与 Chromium 的观测，不是原生应用的进程总内存，也没有据此宣称完整性能问题已经解决。

编辑历史共享不可变的原包与媒体字节。PDF 库、字体处理库及中文字体在首次需要 PDF 或放映时加载，普通新建和 PPTX 编辑不加载旧 WASM。后续桌面包仍需分别记录 Windows WebView2 与 macOS WKWebView 的实际启动、内存和保存结果。
