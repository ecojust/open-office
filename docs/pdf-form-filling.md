# PDF 现有表单填写

后续已增加[正文替换与交互对象保护](pdf-text-object-protection.md)：正文工具不能覆盖表单外观后误称原值已被删除；表单内容仍通过本页描述的填写功能修改。

PDF 侧栏新增「表单」：列出当前页已有的字段，点击字段名或页面上的蓝色框可定位、填写，再点击「应用填写」。应用会改写真正的 PDF 字节，支持撤销、重做、保存和重新打开；尚未应用的内容会阻止切页、改选字段、保存及撤销，避免丢失草稿。

## 本轮支持与边界

| 字段 / 文档 | 行为 |
| --- | --- |
| 独立、名称唯一的普通文本框 | 单行、多行、空值、最大长度检查；验证中文与拉丁文字保存后的值及外观 |
| 标准字体 | 仅接受经资源验证的 Type1 Helvetica、Courier、Times-Roman，WinAnsi 或缺省编码，无自定义 FontDescriptor；不悄悄替换用户字体 |
| 独立复选框 | 勾选 / 取消，沿用原自定义开状态名称（包括空格转义）；同时修改 `/V`、`/AS`，保留原开关外观流 |
| 只读或锁定、密码 / 分格 / 文件选择 / 富文本等特殊文本框 | 显示明确只读原因；密码值不在字段列表返回 |
| 单选、下拉、列表、按钮、签名字段 | 保留现有内容，暂时只读 |
| Parent / Kids、复杂字段树、重复字段名 | 暂时只读；名称检查覆盖整个文件，不仅当前页 |
| XFA、动作、JavaScript、计算链、需要阅读器重建全部外观 | 表单只读；不执行文档脚本或自动计算 |
| 自定义 / 嵌入字体、缺少可验证外观、文本框滚入/按下外观 | 暂时只读，避免错误重建外观 |
| 虚线边框文本框 | 暂时只读；当前本地外观生成器会将虚线重建为实线，不能保真填写 |
| 仅从文档级 `/DA` 继承文字外观的文本框 | 直接填写暂时只读，避免底层错误改成黑色自动字号；页面合并时会先将来源默认外观落实到各自字段 |
| 浏览器无本地后端 | PDF.js 预览已有外观；完整填写与保存需要桌面本地 PDF 后端 |

这不是表单设计器：本轮不创建、移动、删除或重命名字段，不提交表单，不自动执行必填校验或发送内容。必填状态只作为提示，允许保存尚未填完的草稿。长内容仍受原框尺寸限制，需要检查字形及是否显示完整；复杂文字排版和任意字体保真未作保证。

## 值、外观与原文保护

- 填写按 `fillForms` 权限检查，与「修改原文」「添加批注」权限独立。只有填写权限的加密 PDF 也可以填写；未经授权的操作在后端再次拒绝。
- 保存保留原加密方式与密码/权限；签名文档沿用「编辑副本」确认及另存保护，不承诺编辑后原数字签名仍有效。
- 文本修改先生成新的普通外观，再恢复原字段字典，仅转移 `/V` 与新 `/AP/N`。保留默认值、字体定义、边框、填充、标记、位置和未知字段属性；共享外观先分离，避免误改另一字段。
- 复选框复用原外观，不重新绘制打勾图形，不将自定义名称改成固定 `Yes`。无法可靠解析的特殊开状态名称只读。
- 填写不对子集字体做全文重写，不压平表单。字段仍可由其他阅读器读取和继续填写。
- 字段请求带整份源文件及字段对象的 SHA-256 token，前端另检查文档修订号。保存会整理 xref，因此应用、撤销、重做后重新检查序列化字节，使用新字段标识。
- 全文检查上限为 2000 个字段、5000 条批注；超出后只读。每次返回最多 500 个字段、限定字符预算和最多 50 页。既有 40 MiB 文件、500 页及本地进程边界继续生效。

## 固定源码与 REA 对照

参考公开 `ONLYOFFICE/sdkjs@72b0421c0bbf9d01eed9cf14834ae47eb2df1b50` 的七个精确函数摘录，独立实现产品逻辑，没有复制 SDK 源码进入产品：

- `CBaseField.IsReadOnly` 会从父字段继承状态。
- `CTextField.SetValue` / `Commit` 区分值和显示，提交时会同步同名 widget、父值，并执行格式动作。
- `CTextField.DoFormatAction` 会调用脚本动作；本应用将此类文档只读，不执行该行为。
- `CBaseCheckBoxField.SetValue` / `SetChecked` / `WriteToBinary` 分别处理导出值、勾选状态及保存元数据，不能把所有复选框简单视为固定 `Yes`。

### 后续共享样式复查

定向复查发现：两个字段共用间接 `/BS` 边框字典时，仅填一个字段也会通过 `Widget.update` 把合法的小数虚线数组 `[2.5 1.25]` 四舍五入成 `[3 1]`，连未修改字段的样式元数据也被改动。只恢复字段顶层字典不足以阻止这种共享对象写入。

修复在生成外观前为 `/BS`、`/MK` 建立私有字典副本，并保留原始颜色及虚线数据，不通过经过舍入的属性回写。保存时仍恢复原字段字典和共享引用。另将无法保真重建的虚线文本框明确只读；同页其他普通字段继续可编辑。

新增 3 项回归后，表单后端 **17/17** 通过：两次连续保存保留共享样式字典和其他字段值/外观、页面正文及另一页像素；虚线框只读但相邻字段可编辑且不影响原框；独立字段的 0/90/180/270 度旋转保持 `/MK`、外观 `/Matrix` 与 `/BBox`。这是定向后端复查，前述界面 9/9 与 26/26 为此修复前的验收记录，未据此宣称重新执行界面或桌面安装包测试。

### 页面调整与合并后的表单

进一步检查确认，底层 `Document.select` 会在提取、删除和重排时移除根 `/AcroForm`，即使页面里的 widget 仍然存在。现在先验证简单平面字段结构，操作后恢复原表单默认值与资源，只将根 `/Fields` 筛选为保留页中的字段。提取后的普通表单可以继续填写；调整页面时不对原有表单字体做子集重写。

同一 PDF 合并两次时，保留两套独立字段，为重名字段生成独立名称并提示用户；不将它们组成共享值的父子字段。来源文件的默认文字外观 `/DA` 与对齐 `/Q` 会落实到其各自字段，避免第二份文件改变第一份的填写样式。底层自动生成的空 `/CO []` 不再被误判为活动计算链，真正的非空或异常计算链仍受保护。

含 XFA、关联动作、父子字段、孤立字段或无法验证引用关系的表单，调整或合并页面会明确拒绝，不输出缺失内容的替代文件。本轮没有新增任意字段树的重建，也没有增加直接复制页面入口。
