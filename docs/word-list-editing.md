# 普通段落列表

文字工作台的“开始 → 列表”提供项目符号、数字编号、取消列表、提升一级、降低一级和从 1 重新编号。沿用原有两行工具栏，操作集中在一个侧栏。

## 支持范围与保留方式

- 对普通正文段落创建新的独立列表。创建规则后一次绑定完整选区，不向正文插入伪造的 `1.` 或符号字符。
- 已有普通数字列表和字符项目符号可调整层级；使用只作用已预检选中段落的原生升降级命令，不修改共享 `NumberingRules`，不递归调整未选中的子项。
- 取消列表使用原生段落编号关闭语义，不替换正文、链接、字段或文字格式。
- 用原生 `ParaIsNumberingRestart` 与 `NumberingStartValue` 为选区首段设置重新开始标记，不重写共享规则的起始值。同一列表后续编号的实际影响由原生引擎与保存重开验证。
- 每个操作放入一个原生撤销组。点击时最多进行 4 次只读检查、间隔 60 毫秒，取得连续两次稳定版本；每次文档、完整选区、列表摘要和段落信息都必须一致，才提交一次严格操作。失败不会自动重放，持续变化会明确提示稍后操作。列表操作不加入即时格式命令通道。

本轮支持独立逐级十进制数字和常见字符项目符号。章节标题、父级联动编号、图片符号、未知规则、表格或分区内的列表、不同列表混合选区会明确拒绝，保留原文档。切换列表类型需要先取消再创建。暂不提供“接续前一列表”，因为它需要验证兼容列表实例语义，不能只设置一个显示数字。

一次最多处理 100 个段落、单段 20,000 字、合计 64,000 字。所有目标段落先完整预检；选区的独占末端恰好位于下一段开头时，不把该下一段算入本次操作。工具栏摘要只检查当前层并按文档代际、版本和选区缓存，完整规则检查留在实际操作时执行。

## 验证

- `tests/writer-lists.test.mjs`：列表创建与独立规则、原子拒绝、层级、撤销组、选区边界、文档生命周期及摘要缓存的 54 项契约测试，使用原生接口测试替身，不证明实际渲染、撤销或文件回转。
- `tests/writer-list-ui-state.test.mjs`：实际组件脚本与 Vue watcher 的 34 项状态测试，验证稳定读取上限、目标一致性、失效选区、草稿、切换、卸载与重复点击不产生旧请求重放。
- `tests/browser/word-lists-ui.cjs`：通过实际 Vue 查找和列表按钮操作，再原生导出 DOCX/ODT 并重新打开；不注入写入钩子、不回填源文件。
- 独立小样本包括共享 abstractNum 的不同列表实例、嵌套条目、预先存在的中断后接续结构、起始值 7 的 override，以及粗体、链接和 PAGE 字段。包内容以原生稳定导出的基线比较，区分正常格式标准化和误改。
- 独立实际内核完整规则审计完成 59 步、42 条操作记录，36 个 DOCX/ODT 对比阶段的 2,922 条 XML 检查通过。这一轮验证原生层级命令、边界与保留行为，早于最后的规则生命周期修复；不把它当作最终版本全部功能的重复证明。
- 最后的生命周期定向完成 34 步，4 个 DOCX/ODT 对比阶段的 332 条独立 XML 检查通过：连续两次撤销和重做恢复正确类型，显式 GC 压力下重做记录保留，成功重开文档后规则引用数由 2 变为 0，新文档重新创建后为 1。只读计数与 GC 属于专用测试钩子，实际界面回归不使用这些钩子。
- 最终真实 Vue 界面完成 12 项检查：创建、取消、升降级、重新编号、原生撤销重做、DOCX/ODT 导出重开后继续编辑，以及桌面/窄屏截图。输出为 `test-results/word-list-iteration/ui-final-complete`。其 4 个包对比阶段、350 条独立 XML 断言全部通过；正文格式、链接、PAGE 字段及非目标列表保留。

测试输出默认位于 `test-results/word-list-iteration`；最终报告记录通过项与实际导出文件。以上是有边界的普通列表支持，不代表任意复杂编号模板都可从侧栏编辑。

可用 `APP_URL=http://127.0.0.1:5199 OUTPUT_DIR=test-results/word-list-iteration/ui node tests/browser/word-lists-ui.cjs` 重跑界面流程。随后运行 `python3 tests/browser/word-lists-ui-audit-plan.py <界面输出目录> <审计目录>` 生成计划，再运行 `python3 tests/browser/audit-word-lists.py <审计目录>/xml-plan.json` 独立检查导出包。

实际内核将不存在的默认 `TextSection`、`TextTable`、`NumberingRules` 接口表示为 `undefined`。仅在属性存在、成功读取且状态明确为 `DEFAULT_VALUE` 时将其归一化为空接口；未知状态、直接值 `undefined`、异常或非接口假值仍拒绝。首次失败及独立原始属性证据保留在研究目录的 `word-list-review/initial` 与 `native-empty-diagnostic`，没有取消结构检查来绕过这一差异。

实际导出审计还发现段落和文字光标的 `NumberingLevel` setter 都无法真正撤销层级，即使撤销管理器存在操作组。最终改走固定内核源码可核对的 `IncrementLevel` / `DecrementLevel` 非递归命令（`SwUndoNumUpDown`），并在执行后验证实际层级。失败轮次 `nullable-fixed` 和 `cursor-level-fixed` 保留了原生撤销队列与 DOCX/ODT 证据。

自建圆点列表导出 DOCX 后，原生重开返回 Symbol 字体、字符 U+F0B7、字符集 10，并以相同字形表示 suffix / ListFormat。这一完整组合按普通圆点处理；未知字形或字体组合仍拒绝。DOCX 只有九级，内核补出的第十默认槽位允许另一种基本类型，但仍检查其全部规则；侧栏只能操作 0–8 级，不写该默认槽位或任何共享规则。原始重开证据保留在 `reopened-bullet-diagnostic`。

ODT 重开把普通 Unicode 圆点的 `ListFormat` 表示为当前层占位符 `%1%`、`%2%` 等。仅在普通字符、空前后缀、独立单级编号语义都成立时接受这种对应关系；跨层引用、多个占位符和附加文字仍拒绝。原始证据保留在 `reopened-odt-diagnostic`。重开后的比较使用同次导入、尚未编辑时导出的基线，避免把原生过滤器重新命名样式误认为此次层级操作的改动。

真实撤销历史还显示，创建 `NumberingRules` 自身会产生原生“创建编号样式”记录。该记录可能在规则初始化完成前因读取撤销标题而固定默认数字模板快照，之后的初始化不会使快照失效。仅把创建与绑定放进同组，实际重做圆点列表错误恢复成了数字列表；这一失败的 DOCX 与报告保留在 `ui-final`，早先重做丢失编号的证据保留在 `ui`。

内部规则创建和初始化使用原生撤销管理器的 `lock` / `unlock` 暂停记录，不清除现有撤销或重做历史；解锁后才将绑定作为一个用户可撤销操作。已有锁或未知接口会在创建前拒绝，初始化失败也在 `finally` 解锁且不绑定正文。规则工厂对象按当前文档保留，避免未使用时被提前销毁；原生文档成功关闭后才释放。每次打开最多创建 512 个规则实例，达到上限会提示保存并重开，已有列表仍可编辑，不淘汰可能参与撤销的实例。规则包装对象的垃圾回收影响有源码依据，但此前失败的实际 GC 时序未确证，不声称已证明唯一根因。
