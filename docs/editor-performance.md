# 编辑性能验证

## 本轮修改

- 演示画布缓存最近访问的 4 页，通常最多保留 64 MiB 的 RGBA 像素。单页超过预算时只保留该页，保持当前显示清晰度；纹理尺寸仍受渲染器上限约束。
- 缓存随文稿内容、页面顺序、主题、字体及相关显示参数变化而更新。修改后切回、撤销以及切换文档，都必须显示对应的最新内容。
- 缩略图只绘制当前可见的条目，保留列表布局和拖动目标。
- 顶部文档标签切换只处理尚未完成的输入，保留各文档的内存模型和撤销历史，不再为切换导出完整文件。实际保存仍校验导出的文档版本；未完成的批注仍需处理。
- 文字文档通过共享数据标识跳过未变化的正文、图片及保留数据比较。实际内容变化时仍完整检查保存状态，撤销到已保存内容时恢复为未修改状态。

## 复现与检查

```sh
npm run test:browser:ppt-render-cache
npm run test:browser:live-tabs
```

前者使用真实缩略图点击和文字输入，检查渲染次数、纹理上传、资源请求、修改与撤销后的画面，以及缓存淘汰。后者检查各类文档切换时没有完整导出，同时保留输入、未保存提醒、保存版本校验和关闭确认。

标签切换回归按文字、表格、演示和 PDF 分组，每组与笔记本交叉切换，使用独立浏览器进程控制内存占用；共 29 项通过。文件保存接口由测试替身提供，导出的文档内容会重新导入验证。这不覆盖五种引擎同时常驻、系统文件对话框或真实磁盘写入。

排查时，默认三页演示在连续切换页面期间没有新增文档资源请求，原实现却在每次切换后重新绘制整页并上传纹理。因此这轮主要减少重复绘制；不能仅凭切页卡顿判定是图片下载。

2026-10-16 的真实浏览器回归中，连续 6 次切页的整页纹理上传由基线的 6 次降为 2 次；后 4 次访问已见页面没有新增画布绘制，资源请求为 0。文字输入后画面更新、后续缓存像素一致、跨文档切换、撤销以及 5 页的缓存淘汰检查均通过。该结果说明减少了重复工作，不等同于整体速度提升比例。

浏览器测试使用实际 Rust/WASM 引擎。软件图形渲染、编译争用和不同设备都会影响耗时，不能把 Linux 测试耗时当作 macOS 原生性能，也不能据此推断所有文档和操作都已流畅。
