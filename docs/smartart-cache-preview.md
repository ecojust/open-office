# SmartArt 缓存预览

本文记录缓存显示能力；后续已增加[受支持节点文字编辑](smartart-text-editing.md)，对应数据与缓存会按明确编辑意图更新。

本轮针对公开 Apache POI 测试文件中已经保存的 SmartArt 绘图缓存实现预览。实现依据是 OOXML 文件结构和实际对照观察，没有复制 ONLYOFFICE 源码。

## 已实现

- 从 `diagramData` 的 `dataModelExt` 解析正确的本地 `diagramDrawing` 关系，支持幻灯片拥有关系和数据部件拥有关系两种结构。
- 显示缓存中的矩形、圆角矩形、椭圆、六边形、基本连接线及受限分组。
- 保留图框负坐标、绘图坐标、独立文字框和形状与文字的组合旋转。
- 支持基本文本样式、主题颜色、HSL 颜色变换、透明度、线性渐变、局部内嵌图片和形状裁剪。
- 生成最长边 1024–2048 像素的缓存 PNG，由编辑画布、缩略图、放映和 PDF 共用。每份文稿最多 64 个缓存和 3200 万预览像素；每个缓存的图片解码预算为 2000 万像素。
- SmartArt 仍受保护，不能通过普通文字编辑或删除动作误改。无节点编辑时保存继续使用原始图表 XML、关系和媒体字节，缓存 PNG 不替换原图表结构。

## 明确边界

这不是完整的 SmartArt 编辑或布局引擎。缺少缓存、外部缓存/图片、不支持的路径或超出资源预算时，使用受保护占位并说明原因。未生成节点、未重算布局，原始内容保持在 PPTX 中。

缓存预览是有分辨率上限的光栅，PDF 中的 SmartArt 也作为图片嵌入；其中的文字不能作为 PDF 文本检索。没有把空缓存文字替换成原编辑器显示的 `[Text]` 占位提示。复杂文字段落、三维和高级效果尚不完全对齐。

带 `fillRect` 的图片填充与参考软件存在已确认的边界差异：样本的图片圆几何为 13.5749 × 13.5749 mm，参考软件运行时用于填充的边界却为 13.9277 × 27.4320 mm。原 JPEG 字节一致、没有 EXIF 旋转，额外拉伸来自绘制边界。当前按文档保存的几何与填充参数显示，未针对这份样本硬编码两倍拉伸，也不宣称逐像素一致。边界高度为何扩大仍未完全隔离。

测试时还发现空白或纯图片演示导出 PDF 会卡在 CID-CFF 空字形子集。现在给字体资源预留一个空格字形，不绘制到页面，修复导出挂起。该修复仍保留原有 PDF 中文字体资源的加载成本；没有在这一轮改为按需加载字体。

## 验证

启动开发服务器后执行：

```sh
node tests/browser/smartart-preview.cjs
node --test tests/presentation-pdf-empty.test.mjs tests/presentation-render.test.mjs
```

浏览器回归使用 `SmartArt.pptx`、`smartart-simple.pptx`、`smartart-rotated-text.pptx` 三个独立样例。每个样例进行三轮保存重开、无关文字编辑后保存、PNG/SVG 预览与 PDF 导出，逐字节比较原图表部件、关系和图片。另检查缓存缺失、外部图片、外部绘图、脚本节点、未知形状、超大解码图片、顶层恒等变换与转义脚本文字八种情况，记录外部请求为零。

`test-results/smartart-preview/report.json` 保存断言结果，子目录包含真实预览、页面截图、PDF 和回存 PPTX。单元测试另验证空白页、纯图片页和缓存图表页的 PDF 可以读取，且资源空格不会变成可见或可检索文字。

这些检查证明本轮声明的缓存显示和保留行为，不代表任意复杂文档无损兼容。
