# 本地笔记本

0.12.0 新增笔记本工作区，使用 `.oonote` 文件保存分区、页面及其内容。新建、打开、保存、另存为、打印、主题和文档标签由顶部工作台统一管理。本页描述当前源码功能，本轮安装包仍待构建与原生验收。

## 功能

- 通过分区和页面整理笔记，支持新建、重命名和删除；删除前弹窗确认。
- 正文支持标题、粗体、斜体、下划线、删除线、项目列表、编号列表和待办勾选。
- 插入 PNG/JPEG 图片，图片内容随笔记文件保存；支持搜索笔记内容、撤销和重做。
- 打印当前页面。笔记本没有直接导出 PDF 命令；可通过系统打印对话框提供的存为 PDF 功能输出当前页。

桌面版打开已有 `.oonote` 后，“保存”写回原文件，“另存为”选择新的位置。新建笔记本需先手动保存；启用自动保存后，每 30 秒保存已选择本机位置的当前文档。尚未确认的输入不会被后台保存强行提交；旧保存回执不能清除较晚编辑的未保存状态。

## 文件与实现

笔记本使用本地 TypeScript 结构化模型，由 `src/notes/` 和 `src/components/NotebookEditor.vue` 实现。文件是 UTF-8 JSON，根标识为 `format: "open-office-notebook"`、`version: 1`，包含笔记本、分区、页面和内容块；图片以 PNG/JPEG 数据保存。不将任意 HTML 写入笔记文件，打开时校验格式、标识、内容与大小。

当前文件上限为 16 MiB，单张图片上限为 4 MiB。它不是第五套 Rust/WASM 引擎，也不读取其他笔记软件的专有文件格式。暂不提供云同步、局域网共享、手写识别或附件管理。

## 验证范围

模型与会话回归入口为 `tests/notebook.test.mjs`，全局文件和标签生命周期由 App 回归覆盖。`npm run test:browser:notes` 检查真实界面的编辑、删除确认、主题、窄屏、下载重开和批量关闭；本轮已通过 10 组检查，下载与重开后再次保存的文件摘要一致。

上述浏览器检查不覆盖系统输入法、打印对话框、原生文件对话框和各平台安装包，这些仍需分别验收；四套 Rust 编辑器已有报告不能直接作为笔记本通过的证据。最新构建流程见[开发文档](development.md)。
