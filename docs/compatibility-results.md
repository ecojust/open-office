# 复杂文档兼容性回归

日期：2026-10-13。对照目标是 Microsoft 365 桌面版的本地文档能力；账号、云盘、云协作、云 AI 与联网内容服务永久排除。功能范围分别见 [Word／Excel](word-excel-365-parity.md)、[PowerPoint](powerpoint-365-parity.md)、[PDF](pdf-capabilities.md)及[本地办公范围](local-only.md)。

本轮没有安装或运行 Microsoft Office。测试通过本应用的 Vue `OfficeEditor`、随包 LibreOffice WASM 和本地 PDF 后端完成，不把公开功能说明、内核菜单、文件能打开或对象数量相同当作完整兼容证明。尚未完成 Microsoft 365、WPS、ONLYOFFICE 原应用中的双向互验，也不宣称功能严格完整对齐。

## 样例与方法

[固定语料清单](../tests/compatibility/manifest.json)含 23 份独立源文件，覆盖 DOC、DOCX、ODT、RTF、XLS、XLSX、ODS、PPT、PPTX、ODP。13 份为原创生成的复杂场景，7 份来自 Apache POI，2 份来自 ONLYOFFICE 官方样例仓库，1 份为 Apache Tika 收录的 WPS 附件文档。来源提交、SHA-256、文档声明的生产软件和许可证全部保留；声明的软件名称不等于亲自观察作者在该应用保存。

复杂场景包括 20 个分节的横竖版 Word 报告、修订/脚注/嵌套表格、2000 行和 4000 多个公式的工作簿、1904 日期系统、验证/条件格式/透视表、20 页带图表/备注/隐藏页的演示以及动画/嵌入声音。WPS 样例仅覆盖 9 个嵌入附件及预览图，没有正文，不执行附件，不能据此推广 WPS 复杂正文或表格兼容性。

每条格式分支按以下顺序执行：导入原件 → 保存 → 重开 → 加入编辑标记 → 保存 → 重开 → 再保存 → 最后重开。第二轮在 Word 中插入非覆盖文字，在 Calc 中新增独立校验页，在演示中追加备注。每次保存都与最初的独立源解析比较，而不是只与上一次可能已丢失数据的结果比较；最后另导出 PDF，使用独立解析器确认可读页，并留存截图。

现代格式与 ODF 分支分别从原件开始。结果区分“已核验字段通过”“仍需复核”“实际差异”和“为避免丢失而拒绝转换”。旧 OLE 文件的独立语义解析不完整；有些 ODF 引用、合并单元格和条件格式的跨格式等价性未得到证明，明确保留为复核项，不计入完全通过。

PDF 另用 12 页原创复杂样例，在真实 `PdfEditor` 中完成三次修改、保存、关闭和重开。包含中英文、图片/表格、书签、链接、批注、表单、旋转页及裁切页；其中一轮修改旋转页，一轮只在指定页添加中文水印。独立 PyMuPDF 比对未修改页面的像素和对象元数据。

## 运行结果

首轮 `local-only-full` 对 22 份文档执行 44 条格式分支：43 条完成各三轮保存和最后重开，共 129 份保存产物；动态演示的 ODP 分支按保护策略拒绝保存。22 份原件均完成原生离线入口检查，外部网络请求和页面异常为 0。另有 WPS 附件样例单独完成 DOCX／ODT 各三轮，共 6 份产物、2 条最终重开分支。两轮覆盖 23 份独立原件；诊断期间有源码修改，不能把这些历史结果当作最终候选提交全部通过。

独立检查器曾将 RTF 单元格边界、ODF 批注元数据、位图样式引用、页眉制表位置和空页脚匹配错误当作内容丢失。已补负例修正，并对**同一批、哈希未变的产物**重新解析；原浏览器报告保留。复核后首轮为 15 件待复核、7 件有实际差异或受保护的转换拒绝，没有“全部格式完全通过”的样例；其中两件图表问题由后续源码修复，最终回归单列。WPS 专项证实附件内容丢失，按失败计入，不能被通用对象数量检查覆盖。压缩后的[浏览器结果索引](../tests/compatibility/results/browser-summary.json)保留分支、失败和复核原因。

修复后的 `local-only-final` 于 06:16–06:22 UTC 对 12 份重点样例执行现代格式各三轮，**36 次保存全部成功且全部实际重开**，12 份原件通过原生离线入口检查，外部请求和页面异常为 0。环境为 Linux x64、Node 24.19.0、Chromium 154.0.8037.57，运行开始和结束的产品源码指纹一致。独立复核及[再次执行的附件审计](../tests/compatibility/results/wps-attachment-final-audit.json)合并后：3 件的已检查字段通过，6 件仍需复核，3 件存在已确认差异（布尔值/隐藏级别、UNIQUE 重算、WPS 附件）。此前两份 PPTX 的图表公式和内嵌工作簿丢失不再出现。这个结果不是“12 份全部兼容”，也不把首轮未复跑的分支改标为已修复。

PDF 三轮实际操作通过：未修改页像素一致，书签、链接、图片、批注、表单及旋转裁切信息保持，外部请求、套接字、HTTP 失败与页面异常均为 0。见[PDF 结果索引](../tests/compatibility/results/pdf-summary.json)。这不证明表单编辑、证书签名、OCR 或任意复杂 PDF 均兼容。

## PPT 图表修复

原生导出曾保留图表缓存，却丢失 `externalData` 的可编辑工作簿，并把原系列公式改成内核内部名称。本轮修复同时要求原生修改监听、页面/对象身份及当前数据检查，才允许恢复未修改图表的源工作簿；仅缓存值相同不足以推断数据来源没有修改。目标已有有效绑定时优先保留目标，修改数据时为当前系列生成新的本地 XLSX，不填回旧值。

图表模型会在选页、重排过程中销毁重建。仅本应用受控的同步选页/移页操作，在之前未编辑、期间无真实修改事件、页/形状身份不变且新模型清洁时续接监听；其他销毁、替换、过期或不明来源仍拒绝旧工作簿恢复。图表原始来源快照与可修改的转场/媒体快照分开保留，避免重排后错误匹配。

实际 DOM/ZIP 的 15 项回归，以及实际 WASM 的 8 项专项通过：把数据 24 改为 99 后图表缓存、内嵌 XLSX 和重开结果均为 99；组合修改转场后仍可保存；真正重排再改转场仍保留原工作簿；复制含图表页后 4 页文稿内有两份可编辑图表并能重开。原生同值编辑但来源已改变的情况不会恢复旧绑定。报告为 `test-results/pptx-chart-data/report.json` 与 `test-results/pptx-chart-native/report.json`，提交中的[图表专项结果索引](../tests/compatibility/results/chart-summary.json)保留检查项及原报告摘要。

复制页的图表按当前类别、系列和数值生成独立工作簿；这一合同不包括复制源工作簿内全部隐藏页、公式、宏或自定义数据连接。多层类别、散点/气泡等尚未证明的数据结构、未知扩展、签名及无法唯一对应的对象会明确拒绝此修复路径，不能据此宣称所有 PowerPoint 图表完整兼容。

## 已确认的边界

- **XLSX 布尔值和隐藏级别**：测试中原生布尔单元格保存为 `TRUE()` 公式，显示值保留，但 `ISFORMULA` 等语义改变；`veryHidden` 变为普通隐藏。这是实际差异，不能因数值相同认定无损。
- **UNIQUE 动态数组重算**：ONLYOFFICE 表格中的 `COUNTA(_xlfn.UNIQUE(C7:C12))` 初次保存仍为 3，第二、三轮的 XLSX 与 ODS 缓存结果均变为 1。仅保留公式文本或首轮缓存不能证明最新函数兼容；本轮未修复该计算差异。
- **透视表显示标题**：上游 Excel 样例的德语行列标题、总计及多选提示在保存后变成字段名或英文提示。已存数值的检查与显示标题检查分开记录，不把本地化变化隐藏掉。
- **WPS 嵌入附件内容丢失**：9 个附件中的 7 个在三轮 DOCX 输出中逐字节相同；另外两个经 OLE `package` 流只读解包复查，源内嵌 Word 的 `docx_content` 在输出中清空，内嵌 Excel 的 `xlsx_content` 单元格及 `Sheet2`、`Sheet3` 消失。第一轮即发生，三轮一致；不能用附件总数仍为 9 判作无损。见[独立附件审计](../tests/compatibility/results/wps-attachment-audit.json)。本轮没有执行附件，也没有修复这一内核转换问题。
- **ODF 页面样式**：原创 ODT 中包含页眉页脚的 `Default` master-page 定义，导入时未成为当前页面样式；转成 DOCX 后该定义及页眉页脚部件未保存。不将此解释成已证明的可见正文丢失，也不声称完整保留所有未启用的页面样式。
- **动态演示转 ODP**：包含或修改过动画、转场、媒体的演示当前要求保存为 PPTX；应用明确拒绝 ODP 转换。这项拒绝保护原内容，测试保留其记录，不能称为 ODP 功能已支持。
- **旧格式只导入**：DOC、RTF、XLS、PPT 的保存默认生成 DOCX、XLSX、PPTX 副本，原格式不能被现代内容覆盖。宏执行、自动外链刷新及加密文件不在支持范围。
- **检验能力边界**：完整排版、字体度量、所有函数重算、SmartArt 语义、嵌入附件执行以及微软原生动画播放没有得到全面验证。图片或对象数量相同只是一项必要检查，不证明外观和编辑行为等价。

针对已测出的 XLSX 布尔值、深度隐藏、UNIQUE 及 DOCX 附件风险，导入会给出具体提示，并将首次保存改为默认带“副本”的另存流程；切换标签和取消保存不清除此标志。保护的是**避免自动覆盖原件**，不把提示当成数据兼容问题已经修复。如果用户在系统另存框主动选择原路径，仍可能经系统确认后覆盖，必须自行保留原件。

## 复现与证据

本轮源码通过 341 项 Node 测试、28 项本地 Python PDF 测试、35 项 Rust 测试，以及独立检查器的 38 项 Python 回归；比较器的 23 项负例/语义检查包含在 Node 总数中，不重复相加。`npm run build` 成功，构建标识为 `2026.1013.1414`。这是本地源码和 Web 产物验证，没有生成新的 macOS/Windows 安装包，也没有运行微软原版进行双向互验。

最终实际文件回归的产品文件集合 SHA-256 为 `107b1bff6f024d5f9c41be2b494926cf0c4854da0f25b17b187c7e4c4891b05e`；详细报告记录每个源文件摘要。文档与测试结果整理不改变这组产品文件。

先准备本项目已固定的引擎、字体及 PDF 本地后端，并在开发用 Python 环境安装 `tests/compatibility/requirements-generator.txt` 中的语料工具依赖，再顺序执行；不同时启动多个 WASM 办公实例。这些语料工具依赖不会加入应用安装包。

```sh
python3 tests/compatibility/generate-fixtures.py --check
python3 tests/compatibility/test_inspect_output.py
COMPAT_RUN=my-new-run npm run test:compatibility
node tests/compatibility/audit-saved.cjs test-results/compatibility/my-new-run/report.json
```

`COMPAT_CASES` 可选择逗号分隔的样例 ID，`COMPAT_MODERN_ONLY=1` 只跑现代格式分支。每个 `COMPAT_RUN` 必须唯一，避免覆盖证据。详细报告、原样保存的输出、独立 XML/PDF 解析和截图位于 `test-results/compatibility/<run>/`。复核脚本只重读哈希匹配的既有产物，另写 `rechecked-report.json`，不覆盖原报告，也不冒充新的浏览器操作。

附件专项用 `python3 tests/compatibility/check-wps-attachments.py` 复现，存在内容丢失时退出码为 1。通过 `COMPAT_ATTACHMENT_AUDIT=<审计JSON>` 传给 `audit-saved.cjs`，会校验源和每份输出的精确 SHA-256，再将已证实的附件内容丢失计入失败；不能让通用比较器的“待复核”覆盖专项失败。

此页描述的是 0.4.0 发布后的源码回归。已发布的 0.4.0 安装包不包含本轮新增的旧格式导入、离线入口限制和兼容修复；新的三平台安装包仍需独立构建和实际启动验收。
