# PPT 表格单元格改字与格式保留

已有表格使用逐格多行输入，不再先拼成 TSV 再拆行。单元格内的换行和制表符不会因此被当作新的行列。新建表格仍可粘贴 TSV；保存过的基础表格也可增加、删除末行或末列。

普通单元格改字沿用普通文本框的有预算文字差异算法。源 `a:txBody` 在独立副本上修改，只替换实际变化的文字，保存对应的显示数据；不回写导入包。未变化的文字片段保留字号、颜色、加粗、上下标及尚未实现的合法 XML 格式。原有 `a:p`、手动 `a:br`、段前段后与行距、段尾格式、`bodyPr`、`lstStyle` 一并保留。单元格属性 `tcPr`、邻格、网格列宽、行高和框架元数据不因改字重建。

这不是原生逐键富文本光标。相同重复文字可能对应多种编辑意图，本实现按确定性的最终文字差异匹配；替换继承起点片段，零宽插入在同一行优先使用左侧片段。未保留的光标意图不能从最终字串恢复。没有 run 的空段落插字继承该段的默认文字格式，不套用段尾格式。

## 编辑边界

- 最多编辑 30 行、20 列，每格 2,000 个 UTF-16 码元。导入的更大表格继续保存原件，并提前说明只读限制。
- 带字段、超链接、关系属性、符号字体、扩展或异常 XML 的格只读。其他安全格仍可修改；同一批修改中只要有一格失败，整批撤回，源包字节与历史不变。
- 合并单元格和带原有动画的表格保持只读。没有猜测合并锚点或改写动画绑定。
- 多种独立格式、手动换行的单元格可在原有行内改字；暂不安全支持增删其换行。可证明使用一致普通模板的单元格可以增删段落。
- 行列调整只适用于与应用基础表格生成模板等价的完整 XML。独立字体/填充、自定义边框、不同列宽/行高、未知属性等会禁用结构按钮，仍允许安全格就地改字。调整尺寸后清理旧坐标对应的文字数据，保留表格框架非可视元数据。
- 失败保留对话框草稿；未应用的输入会阻止保存。提交时检查文档修订号，防止旧草稿覆盖新数据。复制、撤销、重做包含持久文字覆盖；复制到其他页时，未修改邻格的关系仍走既有关系迁移路径。

## 显示与兼容范围

单元格的已支持混合文字、段落间距、数字 baseline 和边距使用共享 SVG/PDF 场景，字体诊断也收集实际显示的各段字体。新建基础格的文字坐标和样式与首次保存重开一致。

**本轮完成时的渲染限制（历史记录）**：当时网格按等宽等高展示，主题表格样式、边框、底纹及复杂布局尚未完整实现。后续已增加原列宽/行高和明确单元格底纹，并修复基础表格首次保存重开的背景差异，详见 [PPT 表格布局与明确底纹](presentation-table-layout.md)。内容自动撑高、主题表格样式和边框仍有限制，不声称完整复杂表格视觉等价；图表标题和备注编辑不在这些迭代范围内。

真实 Vue 操作覆盖混合格改字、撤销/重做、实际下载与重新打开、失败草稿保留和保存阻止、已保存基础表增减与多行输入，以及 390/320 像素窄屏。报告：`test-results/presentation-table-text-ui/report.json`；截图：`test-results/presentation-table-text-ui/table-text-reopened.png`。为便于观察，UI 测试先通过真实属性输入扩高表格并保存基线，再进行改字比较。
