# 办公模块完善：独立审查与验收计划

> 本文记录四工作区完善阶段的基线；后续普通文本框内容编辑、对象属性保留与附件保护修复见[文件保留迭代](compatibility-preservation-iteration.md)。
日期：2026-10-14。状态：四模块源码与专项报告独立复核完成；主代理的最终全量构建与外部原生补充验收另行记录。本文件区分实现、源码审查及实际报告，不将单项结果扩展为全部兼容性结论。

## 当前架构

| 模块 | 编辑与保存链路 | 本轮计划 |
| --- | --- | --- |
| Word | 中文 Vue 工作台 → 同源 iframe/worker → ZetaOffice/UNO Writer → DOCX/ODT/PDF 导出 | 查找后的当前匹配项替换、超链接元数据、高亮与上下标 |
| 表格 | 中文 Vue 工作台 → 同一办公引擎的 Calc 原生对象 → XLSX/ODS/PDF 导出 | 原生相对公式填充、选区统计、单格数据验证/条件格式只读查看（未扩展管理） |
| PDF | PDF.js 展示；本地 Python/PyMuPDF 对输入字节副本操作；验证新文件后替换当前字节 | 当前页批注列表与定位、便签、备注修改及单项删除 |
| PPT | 独立 TypeScript 模型/OOXML 读写、统一预览；原始包另存并保留 | 已有局部字符格式基础上的指定段落格式、文本框布局控件 |

当前源码并没有替换 Word/Calc 的原生办公内核。`src/office/README.md` 已将当前架构与旧 Impress 适配层/0.4.0 安装包说明分开，明确默认 PPT 使用独立编辑器。每个模块的交付结论绑定本轮代码和实测报告，历史安装包验收不自动覆盖这些新增能力。

## 跨模块复核要求

1. **保存的证据分层。** UI 显示、内存模型、保存后重新打开及独立文件读取分别检查。保留未知 XML 不等于完整渲染；原生内核提供 API 不等于工作台已经支持它。
2. **目标身份必须完整。** 编辑绑定文档、版本、选区或对象；异步读取还绑定工作表/页和范围。切换文件、切页、撤销或修改后，旧回复不得覆盖新的表单或对象。
3. **草稿不能悄悄应用。** 有未提交输入时，保存和切换走既有确认/拒绝流程；错误保留输入，取消不提交。立即操作和有版本约束的草稿操作继续分开。
4. **原件和外部内容。** 原始源文件不在导出完成前覆盖，保存失败不得清除 dirty；链接的存储不触发打开或更新，导入继续禁用宏和外链更新。测试记录外部请求。
5. **事务证据不能跨模块套用。** PPT 采用克隆模型事务，PDF 操作输入字节副本；当前 Word/Calc worker 直接调用 UNO，没有通用失败回滚包装。新原生操作需完整预检、优先单一原生调用，并实测失败后状态与一次撤销行为；不得承诺所有 UNO 异常均自动回滚。
6. **资源预算和平台差异。** 大选区、长文字、批注数量和重复操作有上限，读取不能触发 dirty。Chromium/开发桥结果不替代 macOS/Windows 安装包的原生 WebView 和打包后端验证。

## Word：针对性验收

- 两处或更多相同词：查找下一处后只替换当前命中项；直接改变选择、查询、大小写/全词选项后，不误改另一处。查找本身不改变内容和 dirty。
- 首尾、重复匹配、大小写、全词、中文、跨表格单元格、空选择及截断选择；明确匹配范围和回绕策略。全部替换与单项替换分开验收。
- 新增/更换/清除链接只改目标文本链接属性。保存重开检查链接目标；混合链接回读不得被当成空值自动清除。只接受声明支持的协议；不自动访问链接。
- 高亮新增/清除、上标/下标/恢复普通文本，分别检查实际原生属性和 DOCX 回读；恢复普通文本不得留下缩小字号或基线偏移。
- 新增多属性操作在写入前检查属性支持；无效输入、过期 revision/selection、只读目标不发生部分修改。单次撤销/重做及草稿取消均需原生验证。

## 表格：针对性验收

- 使用原生填充而非 JavaScript 公式字符串替换。以 `=A1+$B$2+C$3+$D4`、区域引用、带空格的工作表名、跨表引用和字符串中的 `A1` 验证相对/绝对引用。
- 仅按实现提供的方向验收；确认来源边保留、目标类型/公式/格式正确，覆盖原目标有明确操作含义。合并、保护、数组公式、多选、越界和过大范围需要明确拒绝或经过验证的原生语义。
- 填充后保存重开计算结果正确，一次撤销恢复整片范围。包含外部引用/联网函数的样本不产生外部请求。
- 选区统计区分非空计数和数值计数；文本数字、公式字符串、空字符串公式、错误、日期/时间、布尔及隐藏/筛选行的处理口径应明确。没有数值时平均值不能误显示有效数字；查询不能修改文档。
- 数据验证至少回读整数、小数、列表、无规则与混合规则。混合选区不能伪装为统一规则；不支持的公式/规则保持只读提示，读取不得自动覆盖。回读响应与 doc/revision/sheet/range 保持一致。

## PDF：针对性验收

- 允许编辑的批注类型限本轮声明范围。只读/锁定、富文本 RC、带 IRT 回复关系的父与子、其他批注类型保持只读。跨页回复和数量上限也检查。
- 用批注 xref 和原始对象校验值确认目标；垃圾整理后重新读取编号。过期 token、错误页、对象被删除、跨文档旧草稿均不误改其他批注。
- 对既有高亮/墨迹只修改备注元数据；独立检查 AP、QuadPoints/InkList、Rect、颜色、不透明度，以及无关链接、表单控件、书签仍保留。未知元数据是否变化以真实回读为准。
- 便签添加和列表定位覆盖 0/90/180/270 度旋转及非零 CropBox；坐标保持与现有 PDF.js/PyMuPDF 换算一致。
- 签名副本、权限限制、未应用草稿、保存失败、撤销/重做和切页行为保留原有保护。成功后检查真实 PDF 批注对象，不只验证界面浮层。

## PPT：针对性验收

- 段落编号对应真实 `a:p`；手动 `a:br` 不产生新段落，空段和尾空段可以独立选择。仅改指定段落指定属性，字符 runs、未选段落、endParaRPr 和其他 bodyPr 不受影响。
- 百分比与固定点值保持不同类型；零段距为显式值；固定行距允许文字重叠。数值按 OOXML 精度统一处理，预览与导出重开一致。
- `spcFirstLastPara` 属文本框级设置，持久化和布局补丁不能将它恢复成旧值。设置文本框垂直对齐、换行和边距时，保留其他未知布局属性。
- 字符选区 → 段落格式 → 字符选区、整框对齐 → 部分段落对齐 → 整框对齐，验证最新明确操作的优先级、源样式重基和撤销/重做。
- 含字段、链接、扩展等对象沿用保守范围，不借本轮放开原有受保护对象。正文修改仍遵守已有首 run 模板政策；本轮不是完整富文本内容编辑器或布局重建引擎。
