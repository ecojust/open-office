# PDF 批注管理：实现与验收

2026-10-14，本轮源码更新。PDF 继续采用 PDF.js 显示、本地 PyMuPDF 1.28.2 写入，不依赖网络服务。本轮没有发布或验证新的桌面安装包。

后续已补上普通独立文本框与复选框的填写闭环，见 [PDF 现有表单填写](pdf-form-filling.md)。本文测试数量保留批注管理这一轮的验收记录。

## 本轮解决的问题

此前可以添加高亮和手绘，但保存重新打开后没有批注管理入口，也无法修改备注或单独删除。本轮补上真实文件编辑闭环：

- 左侧“批注”列出当前页已有批注；点击条目会定位并框出页面上的对象。
- “便签批注”工具支持点击放置、填写中文备注和作者。
- 便签、高亮、手绘可以修改备注及作者。修改只写 `Contents` 和 `T`，保留外观流、颜色、透明度、原有高亮范围及手绘轨迹。
- “删除此批注”删除对应对象；仅想清空备注时可将文字清空后应用。界面明确区分这两种操作。
- 更改参与真实 PDF 字节快照撤销和重做，保存重开仍可管理。尚未应用的草稿会阻止保存、切页、撤销及其他页面编辑，避免丢失。

## 保存与兼容策略

已有批注不被压平成页面图像，也不转换成 HTML 覆盖层。删除单个批注不会删除正文、其他批注、链接、表单字段或目录书签。

只读/锁定标志、富文本备注 `RC`、带 `IRT` 回复关系的讨论，以及当前未实现的其他批注类型均明确只读。跨页的父批注和回复也一起保护；不会将单条备注编辑误当成完整讨论树更新。文档注释权限、加密保留、数字签名“编辑副本”确认继续执行。

保存可能整理 PDF 对象编号，故每次修改后重新读取序列化文件中的批注标识。请求同时验证对象编号与内容令牌；界面另绑定文档修订号，队列拒绝已经过期的操作。撤销恢复非首页时也重新检查正确页面，避免复用第一页的批注缓存。

便签采用 PDF 的标准 Text 注释，四种页面旋转与非零 CropBox 均测试。其 NoRotate 图标在旋转页中的坐标偏移已补偿。批注列表每次最多读取 50 页、1,000 条及 250,000 字；当前界面按页读取。关联关系扫描超过 5,000 条后只读，避免不完整扫描下误删讨论。

## REA 对照依据

固定 sdkjs 提交：`72b0421c0bbf9d01eed9cf14834ae47eb2df1b50`。REA 证据 `ev_4c228dce2d584e8d6311d5a9adc929ad1f195ff4d47970ceae845618a265ae1b` 包含本轮 PDF/PPT 4 个文件、14 个函数、1,276 个 AST 节点，解析失败为 0。

- `pdf/src/annotations/base.js` 的 `SetContents` 与 `SetAuthor` 分别更新备注和作者，而不设置矩形/透明度，支持本轮采用最小字段写入。
- `EditCommentData` 管理完整回复树，因此本轮未将简单文本框直接映射为此类整体替换。
- `pdf/src/document.js` 的 `RemoveComment` 和 `RemoveAnnot` 行为不同。本应用明确区分“清空备注”和“删除批注对象”。

这是实现行为的参考，不是对最终 PDF writer、权限或原生界面的完整解析，也不能替代本应用保存回读验收。实现代码未复制参考软件代码。
