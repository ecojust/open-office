# Paragraph spacing compatibility controls

This corpus checks paragraph line distance and paragraph margins. The older
`independent-word-spacing` corpus tests character tracking and is separate.

`source/` contains complete independently authored DOCX packages, copied byte
for byte from native research. `libreoffice/` contains actual Writer DOCX and
PDF output. `manifest.json` records SHA-256 hashes and independently resolved
paragraph expectations. No native ZIP is filtered to make the application
accept it. `freeze.py` only copies complete files and creates the inventory.

The eight positive pairs cover 18 direct/inherited spacing controls, three
document-default controls, 11 geometry controls, and five real Writer keyboard
actions. The complete `rule-only.docx` source was an unsupported control at the original freeze; the later line-rule compatibility iteration now checks it as a positive without changing its bytes. The original `automatic-color.docx` native output remains unsupported. The initial editing author input omitted explicit color; Writer exported automatic color outside the existing color subset. That evidence is preserved unchanged. The positive editing controls use separate newly authored inputs with explicit black, then repeat the same real native actions.
The native control for a keyboard action is its resulting document, so its
expected text and spacing differ from the untouched source.

The bounded contract is:

- Automatic line height: integer percentages 1–333 (UI multiples 0.01–3.33).
- Exact/minimum line height: 1–18576 twips (0.05–928.8 points).
- Before/after spacing: 0–31680 twips (0–1584 points).
- A direct line value without a rule inherits the effective paragraph rule.
- A spacing element containing only `lineRule` uses Writer's fresh 12-point
  value for exact/minimum, or 100% for auto, overriding an ancestor's value.
  Dedicated source/native controls are in `independent-word-line-rule`.
- Adjacent paragraph margins use the larger of preceding after and following
  before spacing in the continuous preview.

`inspect_docx.py` uses Python ZIP/XML, independently resolves document defaults and
style ancestry, and records raw spacing attributes separately from effective
values. Native automatic line spacing converts twips to rounded hundredths of
a millimetre before deriving an integer percentage; raw 277 becomes 116%.
The corpus expectations were checked against native ODT/DOCX, not generated by
the application. `geometry.py` reads real PDF glyph origins through PyMuPDF.

The browser suite uses actual controls, keyboard selections, file chooser,
downloads, clipboard and Writer resaves. It checks mixed/untouched fields,
selection boundaries, next-style Enter, empty-first-paragraph merging, history,
invalid-input atomicity and DOM cycles. PDF comparisons use glyph-line deltas
for the bounded same-font cases; mixed-font/script evidence is recorded without
claiming exact native shaping or pagination.

Run with Chromium, Python with PyMuPDF, and the pinned LibreOffice available:

```sh
node tests/browser/independent-word-paragraph-spacing.cjs
```

`WORD_PARAGRAPH_SPACING_OUTPUT`, `SOFFICE`, `PYTHON`, and
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` can select local tools/output. Reports pin
product, test, fixture and research hashes and record unexpected network,
runtime, console and page errors. Native editing source/driver/log provenance
is recorded in `research-provenance.json`.
