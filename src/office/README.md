# Offline Writer / Calc / Impress adapter

`OfficeEditor.vue` keeps one ZetaOffice WASM engine in a same-origin iframe. It accepts `document` (id/name/kind/extension/base64/sha256/sizeBytes), with `kind` set to `word`, `sheet`, or `presentation`. This document describes the in-development 0.4.0 adapter, which has not yet been released. Writer, Calc and Impress have Chinese workbench controls that edit actual model objects; a new presentation uses `private:factory/simpress` and defaults to PPTX in the application shell. The component emits `ready`, `dirty`, `status`, `error`, and `request` for desktop file actions. `request.type` is `open`, `new`, `save`, `save-as`, `export-pdf`, `print`, `close`, or `insert-image`; `quit` requests the application's existing guarded exit flow. `request.notice` must be surfaced when present. Generic Export currently routes to PDF with an explicit notice; Save a Copy routes to native Save As. Print Preview remains an engine view, while all print buttons request the shell's explicit “export PDF, then print in a system application” guidance; no system print job is claimed.

Exposed methods:

- `exportFile({format?})`: returns `{base64, extension, name, revision, dirty}`. Writer supports DOCX/ODT/PDF; Calc supports XLSX/ODS/PDF; Impress supports PPTX/ODP/PDF. Export does **not** clear unsaved changes. A PDF export is a copy, not a replacement for the editable presentation tab. These are adapter capabilities; the shell's Save As action currently retains the original document format.
- `markSaved()`: call only after the native filesystem confirms a successful save. It only clears changes if the document revision still matches the exported revision.
- `discardChanges()`: only clears a state already exported at the same revision, preventing edits during a save/switch from being lost. After explicit user confirmation, `discardChanges({force:true})` may discard the current document without that check.
- `undo()`, `redo()`, `search(query?)`, `focus()`.
- `insertImage({name,base64})`: inserts and embeds a PNG/JPEG/WebP/GIF selected by the desktop picker. Impress inserts the graphic on the current slide, preserving its aspect ratio and fitting oversized images within the slide. The adapter limits images to 25 MiB; the shell/native picker may apply a lower limit. The temporary file is not a linked dependency.
- `getWriterState()`, `writerAction(action)`, `writerData(query)` and the corresponding `getCalcState()`, `calcAction(action)`, `calcData(query)` expose the bounded workbench operations. Reads carry document identity and revision; writes validate revision and, where applicable, selection or an explicit table-cell baseline. They do not expose arbitrary UNO dispatch as a general scripting API. Implemented and unverified feature boundaries are listed in [the Word/Excel comparison](../../docs/word-excel-365-parity.md).
- `writerCommand(command)` executes supported immediate actions against a checked current target, using the same channel in the toolbar and native workbench helper. It does not replace strict version/target validation for unapplied drafts.
- `smokeTest()`: only enabled by the optional `smokeMode` prop or a Vite development build. Creates hidden disposable documents; edits Writer original text, saves and reopens DOCX, calculates `SUM(A1:A2)` from 40 and 2, saves and reopens XLSX, then creates a two-slide Impress document, edits existing slide text, and saves and reopens both PPTX and ODP. All three document types are exported as PDF. The resulting JSON includes actual reopened text/formula/value, slide count, and byte sizes/PDF signatures. The native smoke flow independently inspects the Impress PDF through the PDF backend and requires two pages. These round trips do not verify native slideshow or animation compatibility.

Adding a slide inherits the current slide's layout and master without copying its text or images. The bundled WASM engine's native slideshow is not enabled: F5 and built-in slideshow menu actions route to the application's independent player. It renders static PDF pages and adds six supported page transitions, automatic advance, and embedded local audio/video using the application's PPTX feature module. It also provides page navigation, notes, a timer, laser pointer, black/white screen, Escape and browser fullscreen. Media decoding depends on the platform WebView. This is not native Impress or PowerPoint slideshow playback: per-object animation timelines, Morph, Zoom and full media compatibility are not implemented. See [the presentation comparison](../../docs/powerpoint-365-parity.md) for actual test coverage and save restrictions.

The desktop verification flow supplements `smokeTest()` with `native-workbench-smoke.ts`: two DOCX and two XLSX save/reopen cycles, a second object edit, and independent PDF readback. Development commit `293e484` passed that Windows native gate together with the existing presentation/PDF checks. That evidence applies only to that commit and environment; subsequent changes and macOS packages still require their own completed validation. It is not Microsoft 365 interoperability certification.

Local `test-results/` report paths are overwritten by reruns and are not immutable evidence of earlier successes. The current uninstrumented workbench-helper run passes both two-reopen contracts, independent PDF readback and the release report validator. The ten-check full UI success belongs to the preceding code; the new current-target command wiring still requires a full UI rerun and final native-package checks. The draft review/recovery branch has Node and controlled-state Vue coverage, but the earlier WASM UI run did not naturally trigger a late revision conflict. See [the current evidence boundaries](../../docs/word-excel-365-parity.md).

Keep the component mounted when hiding its tab, and resolve unsaved changes before changing `document.id`. Writer, Calc, and Impress tabs share the same engine; do not mount a separate engine for each tab, because the engine starts with a 1 GiB shared WebAssembly memory. `retry()` explicitly asks before discarding in-memory edits. A failed or cancelled native save must not call `markSaved()`.

The native server must serve the full built frontend through loopback HTTP with `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`, and `Cross-Origin-Resource-Policy: same-origin` on all assets. Relative paths preserve the server's unpredictable URL prefix. `SharedArrayBuffer` and WASM threads are mandatory; test actual WKWebView and WebView2 builds, not only Chromium. The iframe protocol validates origin, source window, session, request ID and active document ID. Imported files always use `MacroExecMode.NEVER_EXECUTE` and `UpdateDocMode.NO_UPDATE`; password/macro/update prompts are aborted.

`clipboard-compat.js` handles a Qt WASM startup compatibility issue: Qt discards the promises from `navigator.permissions.query` for `clipboard-read` / `clipboard-write`, while WebKit rejects these unsupported permission descriptors with `TypeError`. The wrapper observes only those two descriptors, keeps the original promise and permission state, and explicitly reports other errors. It does not grant clipboard access; actual copy/paste remains subject to browser and OS permission checks.

Resources are pinned by exact SHA-256 in `vendor/office-runtime-manifest.json`. Run `node scripts/fetch-office-runtime.mjs` during preparation, or use `--verify` for a strictly offline integrity check. Keep giant runtime files out of Git; Vite copies `public/office-runtime` into the distribution. Once packaged, editing never downloads these resources. The engine has English menus; the application wrapper is Chinese, and a bundled Noto Sans CJK SC font supports Chinese document rendering. The engine currently does not import PDF; the separate PDF editor handles original PDF text edits.

Legacy binary DOC/XLS/PPT files are not accepted by the application; convert them to a supported format before opening. PPTX/ODP support does not imply full Microsoft PowerPoint compatibility. Check complex slide masters, fonts, embedded media, transitions, animations, and exported output before delivery; do not claim lossless preservation of every effect or complete PowerPoint feature parity.

Do not describe the complete product as MIT-only: ZetaJS is MIT but LibreOffice, its bundled Qt WASM platform plugin, fonts and other dependencies have separate redistribution/source obligations. See the project's third-party notices and corresponding-source records before distribution.
